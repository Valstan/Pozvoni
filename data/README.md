# Адресная база Малмыжа — предложенная копия по ODbL §4.6

Этот каталог и есть то, что §4.6 требует предложить: **копия базы в открытом доступе,
бесплатно, вместе с машиночитаемым файлом**. Копировать базу в другие форматы не нужно и
вредно: два представления расходятся, а неисправленное расхождение хуже одного формата.

## Что это

Адресный справочник города Малмыжа, которым пользуется поиск адреса на сайте «ПОЗВОНИ»
(`позвони.вмалмыже.рф`). Заменяет внешний геокодер: локальный поиск вместо обращения к
чужому сервису — это и локализация 152-ФЗ, и независимость от чужой сети.

| Файл | Что это |
|---|---|
| `addresses.json` | **сама производная база в полном составе** — та, что отдаётся посетителю в поиске по адресу |
| `osm/malmyzh-raw.json` | исходный ответ Overpass, из которого база собрана; второй экземпляр данных OSM у нас нет, а обновление нужно примерно раз в год |

## Лицензия и атрибуция

- **Лицензия данных:** [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/) (Open Database License).
- **Источник:** данные © [OpenStreetMap contributors](https://www.openstreetmap.org/copyright),
  доступны по ODbL. Строка атрибуции приводится в том виде, как её требует OSMF — вместе
  со ссылкой, а не голым словом.
- **Атрибуция обязана быть видна** вместе с копией, поэтому она лежит и в самой базе
  (`licence`, `attribution` в `addresses.json`), и на странице сайта, и здесь.
- **Граница города:** `relation/2371919` (см. `boundary` в `addresses.json`).
- **Снимок данных:** 2026-08-29T13:13:04Z (`timestamp_osm_base` в
  `osm/malmyzh-raw.json`). Через 12 месяцев в границе города меняется 9 объектов из 3 151,
  поэтому обновление нужно раз в год, а не чаще.

Почему это вообще производная база, а не просто наш файл, — разобрано в
[`../docs/PROBE_MAPS_PROVIDER.md`](../docs/PROBE_MAPS_PROVIDER.md) §9.3: импорт улиц и
адресов в свою базу — это Re-utilisation по §4.4 b, а значит на базу распространяется
share-alike и §4.6.

## Формат `addresses.json`

```jsonc
{
  "source": "OpenStreetMap",
  "licence": "ODbL 1.0",
  "attribution": "© OpenStreetMap contributors",
  "boundary": "relation/2371919",
  "streets":  [ { "name": "Береговая улица", "lat": 56.525422, "lon": 50.66623, "n": 31 }, … ],
  "addresses":[ [ "Береговая улица", "1", 56.528349, 50.668166 ], … ]
}
```

- `streets` — улицы с точкой центра и числом адресов (`n`) для ранжирования результатов;
- `addresses` — кортежи `[улица, дом, широта, долгота]`, координаты в порядке WGS84
  (широта, долгота), то есть **не** в порядке GeoJSON (lon, lat). Путаница порядка —
  источник багов в половине «не работает у меня»;
- `n` в `streets` — счётчик, а не ограничение: он может не совпадать с числом строк в
  `addresses` с тем же именем.

## Как импортировать

Загрузка настолько проста, что отдельный скрипт импорта был бы лишней копией логики:

```js
const db = JSON.parse(await readFile("addresses.json", "utf8"));

// адрес → координаты
const byStreet = new Map();
for (const [street, house, lat, lon] of db.addresses) {
  if (!byStreet.has(street)) byStreet.set(street, []);
  byStreet.get(street).push({ house, lat, lon });
}

// или одним проходом в PostgreSQL
// CREATE TABLE address (street text, house text, lat double precision, lon double precision);
```

Для CSV, если он удобнее, достаточно одной строки: ключи в JSON уже готовый ряд.

## Как обновить

```bash
python scripts/build_address_index.py
```

Скрипт ходит в публичный Overpass **одним** запросом (серия запросов упирается в 429) и
кладёт рядом сырой ответ. Дальше — `npm run data:addresses` и обязательная проверка
`node scripts/check-assets.mjs`: она требует, чтобы лицензия, атрибуция и дата снимка в
`addresses.json` и в этом файле совпадали. Иначе предложенная копия однажды окажется старше
той, по которой работает сайт, — и это будет правдоподобная, но неверная выгрузка.

**Важно:** если вы берёте эту базу, атрибуция OpenStreetMap обязана остаться в вашем
продукте. Это требование ODbL, а не формальность.
