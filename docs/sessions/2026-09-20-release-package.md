## Релизный пакет ел сам себя — сессия 2026-09-20

Задание владельца: `release/` в рабочей копии содержит себя восемь уровней вглубь и вырос
до 49 МБ при заявленных в `docs/DEPLOY.md` 24,5 МиБ. Разобрано и закрыто PR #94
(CI зелёный, squash в `main`, `db90cc6`).

### Причина оказалась не той, что предполагалась

Гипотеза была: копирование `.next/standalone` → `release/` вкладывает прошлый пакет.
Механизм верный, но **втягивает его не общая трассировка, а одна маска.** В
`payload.config.ts` путь задан как `path.resolve(dirname, "payload-types.ts")`, где
`dirname` выводится из `import.meta.url`. В собранном чанке это значение статически не
вычисляется, и `@vercel/nft` вместо одного файла берёт маску — по сути
`**/payload-types.ts` от корня проекта.

Дальше цепочка замыкается: маска ловит копию в лежащем рядом `release/` от прошлой
упаковки → та уезжает в `.next/standalone/release/` → `npm run package` копирует
standalone целиком → `release/release/` → следующая сборка видит уже два уровня.

Видно было прямо в трассе (`.next/server/app/(app)/page.js.nft.json` до правки):

```
../../../../payload-types.ts
../../../../release/payload-types.ts
../../../../release/release/payload-types.ts     ... и так до восьми
```

### ⚠️ Вложенность весила 56 КиБ — и потому жила полтора месяца

Ничего, кроме `payload-types.ts`, в неё не попадало: 8 КиБ на уровень. **49 МБ каталога к
рекурсии отношения не имеют** — это обычный размер пакета (`node_modules` + `.next`).
Ошибка ничего не тормозила и не ломала, поэтому её никто не искал; нашлась случайно, по
глубине каталога. Отсюда третий слой правки ниже: проверка в том же скрипте, который
артефакт производит.

### Прод задет не был

CI собирает из чистого checkout, а `release/` в `.gitignore` — маске нечего ловить.
Проверено на боксе: вложенных каталогов в выкаченном релизе нет, `.env` в пакет тоже не
попадает. Ловушка срабатывала только на машине разработчика, где пакет остаётся лежать
между сборками. «В CI всё хорошо» здесь означало не «ошибки нет», а «у CI другое
окружение».

### Правка — три слоя

1. **`outputFileTracingExcludes: { "**/*": ["./release/**"] }`** в `next.config.mjs` —
   сам разрыв цепочки.
2. **`scripts/clean-release.mjs`** на шаге `prebuild` — убирает не следствие, а вход:
   прошлого пакета на диске просто нет.
3. **Проверка в `scripts/package-release.mjs`** — падает, если вложенный пакет всё же
   собрался.

### ⚠️ `.next/**` в исключения добавлять НЕЛЬЗЯ

Соблазн есть — и это молчаливая поломка. Пути в `*.nft.json` отсчитываются от каталога
страницы внутри `.next/server/...`, поэтому маска `./.next/**` вычистила бы из трассы
настоящие чанки (80 файлов у одной только `/`). Пакет собрался бы, прошёл бы штатные
проверки, запустился бы — и не работал. Исключать надо ровно нарушителя.

### Как проверялось

- **Контрольный прогон.** Подложил `release/payload-types.ts` и `release/release/...`,
  собрал **без** исключения → в `.next/standalone` снова `release/release/`, в трассе три
  записи. С исключением — трасса чистая, в standalone `release/` нет. Исключение работает
  и на Windows (сначала показалось, что нет: симуляция picomatch на `\`-путях врала,
  живая сборка это опровергла).
- Три подряд `npm run build && npm run package` — стабильные 44,5 МиБ, вложенности ноль.
- Штатные проверки пакета (`server.js`, `.next/static`, вырезка карты, адресный
  справочник) проходят; `lint` и `typecheck` зелёные.

### ⚠️ Грабля прогона: `npm run build | head -N` убивает сборку

`head` закрывает пайп, npm получает SIGPIPE и падает молча — `.next/standalone` не
появляется, а `npm run package` потом честно говорит «сначала `npm run build`». Первый раз
это выглядело как провал правки. Полный вывод или `| tail`, не `| head`.

### ⚠️ Трассы переживают пересборку

Вторая проверка дала вложенность там, где её быть не могло: `prebuild` уже убрал
`release/`, а в трассе записи остались — Next переиспользовал `*.nft.json` из кэша, хотя
`next.config.mjs` менялся. Честный прогон — только после `rm -rf .next`. В CI неактуально
(чистый checkout), на машине — помнить.

### Размер в `docs/DEPLOY.md` приведён к факту

Заявленные **24,5 МиБ** (замер 2026-08-29) разошлись с действительностью втрое:
выкаченный релиз — **70 МиБ** (2238 файлов; ~78 МБ на диске, округление по блокам), из
них 21 МиБ сборка, 47 МиБ трассированные зависимости, 2,4 МиБ карта. Разошлись не из-за
вложенности, а из-за роста зависимостей за месяц — спринты 8–9, апгрейды Payload и Next.
В документ записано, что мерить надо **выкаченный релиз**, а не локальную упаковку: под
Windows трассируются другие бинарники и печатается 44,5 МиБ. Строка «~77 МБ на релиз» ниже
по документу приведена к тому же замеру — 78 МБ.

### Что осталось на машине владельца

Прошлый мусор в основном рабочем дереве правка не убирает — следующая сборка снесёт его
шагом `prebuild`, либо разово `rm -rf release .next/standalone`.

### Что НЕ делалось и почему

Глубокая альтернатива — сделать `typescript.outputFile` статически вычислимым, чтобы
трассировщик вообще не расширял маску. Не стал: поле нужно только CLI
`payload generate:types`, а правка в конфиге Payload рискует сломать генерацию типов ради
той же цели, которую закрывает адресное исключение.
