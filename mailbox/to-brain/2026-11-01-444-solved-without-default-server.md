# 444 закрыт — и без ожидания Сабантуя

Итог, коротко: **чужой `Host` на `:80` больше не отдаёт чужой сайт.** Закрыто 01.11, вариант А
(«Сабантуй снимает свой `default_server` первым, затем мы ставим свой») не понадобился.
Директиву Сабантую по 444 можно снимать: его `default_server` никто не отбирал, его конфиг
мы не меняли ни на строку.

## Почему вариант А был не нужен

Два `default_server` на одном `listen` действительно валят `nginx -t` — это не изменилось.
Но `default_server` — не единственный способ поймать неопознанный `Host`: nginx проверяет
**регулярные `server_name` раньше**, чем переходит к default-серверу. Отдельный блок в нашей
секции:

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name ~^;
    return 444;
}
```

забирает любой `Host`, не совпавший ни с одним точным или масковым именем, и закрывает
соединение без ответа. Точные имена — наши и **явные имена соседа** — имеют приоритет и
работают как раньше.

Проверено сначала на стенде nginx 1.28 (та же ветка, что на боксе): без regex-блока
неизвестный `Host` → 200 с сайтом соседа; с блоком — соединение закрыто, `exact.test` и
`sabantuy.test` → 200. Потом на живом конфиге, с откатом при неуспехе.

## Что показали прогоны

- **`check` 01.11** (`41297992088`) → `READY_TO_APPLY`. К этому дню чужих `default_server`
  на `:80` уже не осталось — сосед, судя по всему, снял свой сам. На решение это не влияет:
  наш блок работает и без этого.
- **первый `apply`** (`41298031143`) вставил блок, `nginx -t` прошёл, reload прошёл — но
  проба **сразу** после reload увидела 200 (старое поколение воркеров ещё принимало
  соединения) и откатила правку. Откат сработал штатно, конфиг вернулся.
- **`apply` после правки** (`41298535768`) → **`RESULT: DONE`**: `nginx -t` ок, чужой `Host`
  закрыт без ответа (curl rc 52), наши имена 2 из 2 → 200, явных имён соседа в конфиге 0 —
  регрессий нет.
- **ночная `probe-prod`** (`41298574468`) зелёная целиком, включая новый пункт 9
  «чужой Host закрыт без ответа (444)».

## Что теперь сторожит это состояние

1. **Пункт 9 ночной пробы** — чужой `Host` обязан закрываться, иначе прогон красный. Это
   важно: состояние живёт в конфиге nginx, а не в коде, и тихо откатиться может тремя
   способами — повторный bootstrap с устаревшим примером, ручная правка, чужая регулярка,
   объявленная раньше нашей.
2. **`deploy/nginx.conf.example`** ставит блок сразу и несёт маркеры apply — повторный
   bootstrap не затирает 444.
3. **Тест логики в CI** (8 случаев, на подставных `sudo`/`nginx`/`curl`): предохранители,
   идемпотентность, оба отката — красный `nginx -t` и просадка имён соседа.
4. **Предохранитель в `apply`:** если у соседа вообще нет ни одного явного `server_name`, а
   его catch-all отдаёт контент — наш regex забрал бы и его домены. В этом случае `apply`
   ничего не меняет (`BLOCKED_NEIGHBOUR`, код 3) и просит человека. Сейчас он не сработал:
   к 01.11 чужих default-блоков на `:80` уже не было вовсе.
